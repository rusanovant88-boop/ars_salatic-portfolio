# SALATIC / MANAGER v1

Система управления кейсами твоего портфолио без ручного редактирования JavaScript.

## Открыть редактор

1. Открой **https://app.pagescms.org/** и войди через GitHub.
2. Разреши Pages CMS доступ **только** к репозиторию `rusanovant88-boop/ars_salatic-portfolio`, если интерфейс предложит выбор репозиториев.
3. Выбери репозиторий и ветку `main`.
4. Открой **SALATIC / MANAGER — Projects**.
5. Файл настроек `.pages.yml` уже добавлен. Если редактор предлагает его создать, убедись, что выбрана правильная ветка и обнови страницу.

Не присылай никому GitHub-токены и не вставляй их на сам сайт. Pages CMS сохраняет изменения через авторизацию GitHub.

## Что редактировать

- **Selected works**: 10 исходных кейсов. Чтобы поменять порядок, перетащи элементы списка проектов в редакторе и сохрани. Источник порядка — позиция объекта в `projects`, не поле `order`.
- **Published**: выключить — скрыть кейс на сайте, не удаляя его из данных.
- **Finder filename / Finder role**: название файла и роль в общем Finder.
- **Case title / Full role / Paragraphs**: заголовок и текст внутри кейса.
- **Hover image**: превью в списке (лучше WebP, пропорции 16:9).
- **Video and KV items**: можно добавлять, удалять и менять последовательность медиа. Видео требует `type=video` и числовой `vimeoId`; принт требует `type=kv` и `image`.
- **Desktop case layout**:
  - `split` — текущий оригинальный макет;
  - `wide` — акцент на более широком плеере;
  - `editorial` — широкая текстовая колонка.
  На мобильном пока используется одна адаптивная компоновка: это предотвращает разъезд сетки.

## Добавление нового кейса

В списке **Selected works** добавь объект со следующими полями:
- `id`: уникальная латинская комбинация, без пробелов, например `newProject`;
- `published`: сначала `false`, пока кейс не готов;
- `filename`: например `new_project.mov`;
- `roleShort`: например `sr. art director`;
- `title`, `role`, `preview`, `paragraphs`, `media`;
- `layout`: `split`, `wide` или `editorial`.

Загрузи изображение через встроенный медиа-пикер. Для Vimeo вставляй **только номер ролика**, а не полную ссылку. После проверки выставь `published=true` и сохрани.

Новый кейс появится в Finder автоматически. Тексты, изображения и номера Vimeo больше не требуют обновления `script.js`.

## Публикация и безопасность

- **Save** в Pages CMS записывает изменение в GitHub и запускает обычное обновление GitHub Pages. Отдельной функции «сохранить приватный черновик без коммита» тут нет.
- Для подготовки кейса, который пока нельзя показывать, ставь `published=false`.
- Внешние изображения хранятся в `assets/`. Не публикуй приватные материалы: GitHub Pages и содержимое публичного репозитория доступны посетителям, даже если кейс скрыт в Finder.
- Для восстановления предыдущего содержимого используй историю коммитов GitHub.
- Перед началом реорганизации создана резервная ветка `backup-before-manager-2026-11-05`.
- Не редактируй одновременно `data/portfolio.json` с нескольких устройств.

## Как устроено

- `.pages.yml`: описание полей Pages CMS.
- `data/portfolio.json`: единый источник опубликованного контента и порядка работ.
- `script.js`: подгружает JSON и строит Finder и кейсы.
- `styles.css`: три редакторских шаблона и прежние анимации.
- `index.html`: разметка и резервный статический контент на случай недоступности JSON.

**Важно**: это v1 редактора контента и шаблонов, а не пиксельная верстка в стиле Figma. Возможность свободно двигать каждый элемент на холсте не добавлена.
